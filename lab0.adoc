== Среда разработки программ для микроконтроллера

Для учебных целей используется *IAR Embedded Workbench for Arm*.

=== Состав интегрированной среды разработки IAR Workbench

Процесс разработки ПО включает проектирование (_Design_), разработку кода (_Develop_) и отладку (_Debug_).

=== Процесс создания исполняемого образа

Процесс преобразования кода на C++ в файл с образом исполняемой программы делится на два этапа:

* Трансляция кода в объектный файл.
* Компоновка кода в исполняемый файл.

=== Трансляция кода

Трансляцию выполняет компилятор. На выходе получаются либо файлы библиотек, либо объектные файлы.

=== Компоновка кода

Компоновку выполняет линковщик. На его входе могут быть внешние библиотеки, объектные файлы, стандартные библиотеки C++ и конфигурационный файл, описывающий размещение кода и данных в адресном пространстве микроконтроллера. На выходе — исполняемый файл.

=== Запуск и отладка

Компоновщик IAR создаёт файл в формате *ELF*, который может быть использован для:

* загрузки в систему отладки IAR C-SPY или другой отладчик (например, GDB), способный читать формат ELF;
* загрузки образа в ПЗУ микроконтроллера с помощью программатора.

== Запуск программного обеспечения

Функция `int main()` является точкой входа программы, но до её вызова микроконтроллер выполняет инициализацию стека, глобальных переменных и констант.

=== Инициализация стека

Сразу после подачи питания происходит инициализация указателя стека конечным адресом стека.

=== Инициализация переменных нулевыми значениями

После подачи питания и инициализации стека выполняется функция инициализации памяти нулями (данные, объявленные как zero-initialized data: неинициализированные глобальные переменные, например `int i;`).

=== Инициализация переменных

Далее инициализируются данные, объявленные как initialized data, например `int i = 6;`. Значения инициализации копируются из ПЗУ в ОЗУ.

=== Запуск функции main()

Завершающий этап — вызов функции `main()`.

== Запуск программного обеспечения (продолжение)

=== Файл cstartup.cpp

Действия по инициализации прописываются в файле `cstartup`. Он может быть написан на ассемблере, Си или C++. Пример файла `cstartup.cpp`:

[source, cpp]
----
extern "C" void __iar_program_start(void);

class InterruptHandler {
public:
  static void DummyHandler() { for(;;) {} }
};

using tIntFunct = void(*)();
using tIntVectItem = union { tIntFunct __fun; void* __ptr; };

#pragma segment = "CSTACK"
#pragma location = ".intvec"
const tIntVectItem __vector_table[] = {
  { .__ptr = __sfe("CSTACK") }, // начальное значение указателя стека
  __iar_program_start,          // переход на функцию __iar_program_start

  InterruptHandler::DummyHandler,
  ...
  InterruptHandler::DummyHandler, // TIM4
};

extern "C" void __cmain(void);
extern "C" __weak void __iar_init_core(void);
extern "C" __weak void __iar_init_vfp(void);

#pragma required = __vector_table
void __iar_program_start(void) {
  __iar_init_core();
  __iar_init_vfp();
  __cmain();
}
----

Класс `InterruptHandler` содержит статический метод `DummyHandler()`, который используется как обработчик прерывания по умолчанию (бесконечный цикл). Тип `tIntVectItem` — объединение указателя на функцию и указателя на `void`, что позволяет хранить в таблице векторов как адрес стека, так и адреса обработчиков. Таблица размещается в сегменте `.intvec`, задаваемом в настройках линковщика.

== Использование С++

C++ может заменить Си во встроенной разработке:

* современные компиляторы создают компактный код, не уступающий по эффективности Си;
* C++ — строго типизированный язык, что повышает безопасность программ;
* C++ полностью поддерживает ООП, что удобно для разработки ПО измерительных устройств.

Драйверы для работы с аппаратурой часто уже реализованы производителями (CMSIS, CMSIS_HAL), но они громоздки и не всегда сертифицированы. В курсе C++ используется на всех уровнях: от драйверов до логики работы с пользователем.

=== Программа на С++

В C++ разделяют исходные файлы (`.cpp`) и заголовочные файлы (`.h`, `.hpp`). Заголовочные файлы подключаются через `#include` и вставляются в текст `.cpp` при трансляции.

Пример программы:

[source, cpp, linenums]
----
#include "gpioaregisters.hpp" //for GPIOA
#include "rccregisters.hpp"   //for RCC

int main()
{
  RCC::AHB1ENR::GPIOAEN::Enable::Set();
  GPIOA::MODER::MODER15::Output::Set();
  GPIOA::ODR::ODR15::Enable::Set();
  return 0;
}
----

== Создание проекта и работа в IAR Workbench

* Создать новый проект: *Project ⇒ Create New Project*.

=== Выбор шаблона проекта

* Выбрать шаблон: *C++ — main*.

=== Выбор микроконтроллера

* Сохранить проект.
* В свойствах проекта выбрать: *ST ⇒ STM32F4 ⇒ STM32F411 ⇒ ST STM32F411RE* (правой кнопкой по проекту → Options → General Options → Target).

=== Запуск в режиме отладки

После создания проекта сохранить рабочее пространство (_workspace_). Собрать проект (*Ctrl-F7*), загрузить бинарный файл в микроконтроллер и запустить отладку (*Ctrl-D*).

=== Запуск проекта в режиме симуляции

По умолчанию загрузка и отладка выполняются в симуляторе выбранного микроконтроллера.

Для выхода из отладки нажать *Ctrl-Shift-D*.

=== Выбор внутрисхемного отладчика

Чтобы загрузить программу в микроконтроллер, нужно выбрать внутрисхемный отладчик: *Options ⇒ Debugger ⇒ Driver* → *ST-Link*.

== Структура проекта

Рекомендации по структуре:

* не писать весь код в одном файле;
* каждый класс — в отдельном файле;
* файлы одного компонента — в папке с именем компонента;
* не превращать проект в мусорку.

=== Добавление файла (cstartup.cpp) в проект

Скопировать файл `cstartup.cpp` в папку проекта и добавить его: правой кнопкой по проекту → *Add ⇒ Add Files…* → выбрать `startup_stm32F411.cpp`.

=== Доступ к папке проекта

Правой кнопкой по проекту → *Open Containing Folder*.

В папке проекта находятся папки `Debug` и `Settings`, файлы проекта, рабочей области, `main.cpp` и `startup_stm32F411.cpp`. В `Debug` хранятся объектные файлы, двоичные файлы для прошивки и листинг. В `Settings` — настройки проекта и рабочей области.

=== Структура папки проекта

* Папка `AbstractHardware/Registers` — файлы с описанием полей регистров. Можно скопировать из репозитория преподавателя:

----
git clone https://github.com/lamer0k/CortexLib.git
----

* Папка `AbstractHardware` — файлы для работы с регистрами, аппаратурой и периферией (зависимая от микроконтроллера часть).
* Папка `Application` — файлы классов для логики программы (независимая часть).
* Папка `FreeRtos` — для работы с ОСРВ.

=== Изменение структуры проекта

Создать в проекте IAR группы: *Add ⇒ Group* → `Abstract_Hardware`, `Application`, `Common`, `FreeRtos`.
